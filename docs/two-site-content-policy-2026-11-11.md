# 双站内容职责硬规则（2026-11-11 确认）

> 状态：业务方已确认；所有新页面、旧页面整理、FAQ、博客、导航、站内搜索答案、JSON-LD/Schema、llms.txt、Sitemap 和重定向必须遵守。此规则优先于旧的双站分工方案及旧的涨价专题计划。任何修改须经业务方明确同意。

## 1. 主站：BayMediaStar.com = 办理站

只面向准备**申请、购买、开通、安装、更换或比较套餐**的用户，核心内容：
- 运营商当前可办理方案、官方价格、优惠期限、资格条件、实际月费和一次性费用；报价须核对来源与日期，不能虚构或承诺资格。
- 按完整地址查询可用服务与价格；比较 Spectrum、Xfinity、AT&T Fiber、Frontier 等现有可办理方案。
- 通过鸿达办理的方法：中文咨询、提交申请、开户资格、订单流程、激活、自助安装/上门安装、设备及搬家新装准备。
- 可说明“办理前需确认优惠期后标准月费、设备费与安装费”，属于**新申请价格透明披露**，不算老客户涨价诊断。

**禁止作为主站内容：** 已有客户宽带/手机账单涨价原因分析、两期账单逐项核对、设备异常收费排查、Retention 谈判、历史账单争议、退款、网络故障诊断、老账户费用投诉和以“涨价怎么办”为中心的 SEO/GEO 专题。不能只换标题而保留诊断正文。

## 2. 副站：Oceanver.com = 使用中问题诊断站

专门帮助**已经在使用通信服务**的人理解和核对问题，包括：
- Spectrum 账单为什么比上个月多 $20，逐项检查基础月费、Promotional Discount/Credit、AutoPay、设备费、附加服务、一次性费用。
- Xfinity、AT&T、Frontier、Spectrum 等已有账户账单变化、优惠到期、费用争议、设备异常和网络故障判断。
- 提供可核实的操作步骤、对照表、运营商官方说明及有条件的结论。不得编造客户账单、案例、折扣幅度或保证退款/降价。
- Oceanver 不以新开套餐价格、办理促销、销售申请或客户转化作为主内容。

## 3. 站间和 SEO/GEO 规则

- 一个主题只能有一个明确主归属：**新办理/价格/安装 → BayMediaStar；已有账户/账单变化/故障 → Oceanver**。不跨站复制全文，不重复抢相同搜索意图。
- 主站现有涨价诊断专题要系统清理正文与索引/内链/Schema，不能只隐藏首页入口。既有有价值的办理前说明可保留在办理页面。
- 迁移/撤下已有 URL 前核对索引、流量和历史链接；选择相关目标并验证重定向，不能把所有不同意图的 URL 随意转到同一页面。
- 同属 Bay Media Star Inc. 应真实披露，不得为了 SEO 隐瞒经营主体；**两站电话号码不得混用**。
- Oceanver 新诊断页面不得擅自开放索引或改变全站 noindex/Phase 2 allowlist；需单独批准并核验 robots、响应头、canonical 与 sitemap。
- AI 引用要靠可索引的真实原创内容、准确答案、可靠资料和可见正文；不承诺因 Schema、FAQ 或关键词而被 AI 推荐。

## 4. 变更前检查（必做）

1. 判断目标读者是“准备办理”还是“已经在用”，确定唯一主归属。
2. 检查 H1、title、description、正文、CTA、FAQ、JSON-LD、内部链接、导航、Sitemap/llms.txt 与归属一致。
3. 涉及价格/资格/政策时核对官方来源和核对日期；涉及案例与账单时匿名化并标注证据，不能杜撰。
4. 涉及历史 URL 时检查重定向链、索引、规范网址和原有流量风险。
5. 本地/CI 构建与移动端验证，PR 审核后合并并检查线上；**创建 PR 不等于上线**。
